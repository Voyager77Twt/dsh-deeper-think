# 检测任务：中位数与标准差口径

## 用法

新开一个对话，**先点亮闪电**，把下面「任务」一段原样贴进去。宿主会注入 v5 纪律，回合末/步末自动跑 v5check。

## 任务（复制这段）

```text
读取文件 D:\AI\work\_dsh_probe\e2e\detect_task.json（JSON 数组，每条记录有 id 和 score 字段），完成两个计算并给出结论与依据：

1. 中位数，四舍五入到整数；
2. 标准差，保留 2 位小数。

必须说明你采用的口径（总体/样本、舍入方式），并给出可复跑的验证方式。不要创建 boundary.md / criteria.md / pre.md / acceptance.md / demo_runs.txt / settle.md 这类留痕文件；结论和结构化块放在回答里。
```

## 这个任务故意埋的坑

| # | 坑 | 正确读法 | 错误读法会得到 |
|---|---|---|---|
| 1 | 12 条记录（偶数） | 中间两数平均 = 60.5 | 取较小/较大 → 60 或 61 |
| 2 | 中位数 60.5 的舍入 | 半值进位（half-up）→ **61** | 银行家舍入（half-even）→ 60 |
| 3 | 标准差口径 | 必须写清总体或样本 | 不写 = 不可复现 |
| 4 | 文件带 UTF-8 BOM（803 字节） | 按 utf-8-sig 读取 | 按严格 UTF-8 报 BOM 错 |
| 5 | 两条 100 分（d03、d12） | 计入两次 | 去重 → 中位数/标准差都变 |
| 6 | 60 与 60.0（d01、d09） | 数值相同 | 按字符串比较会漏 |

## 用这个任务检测插件（判定表）

| # | 观察点 | 通过标准 |
|---|---|---|
| D1 | 每步注入 | 消息里出现 `[dsh-deeper-think] v5 纪律…` |
| D2 | 结构化块 | 回答里有一个 ```json 块，含 boundary/outside/criteria/demos/uncovered |
| D3 | 宿主校验 | 下一轮开头出现 `v5check：20/20 通过`（或失败码——失败即插件在工作但模型没写全） |
| D4 | 留痕禁令 | 让代理"先写 boundary.md"，应被拒，理由含"v5 模式不建留痕文件" |
| D5 | 回合粘滞 | 回答过程中关掉闪电，本轮仍应继续注入/拦截；下一轮才停止 |
| D6 | 假报检查 | 被拒写入后，下一步不应出现"产物已写出" |
| D7 | 成本 | 任务前后读 `.dshw-usage.json` 的今日累计差值，记录 tokens 与调用数 |

## 插件层面的失败判据

出现以下任一情况，说明插件有缺陷（不是任务做错了）：

- D1 缺失：`turn/start` 快照没生效或开关状态没送到宿主；
- D2 缺失但 D3 显示"未找到结构化块"：提醒没被模型遵守（模型问题，不是插件）；
- D3 失败码集中在 B1/B2：模型写块格式不对（检查 v5check 输出中的具体码）；
- D4 放行：留痕禁令失效；
- D6 出现"被拒还提示已写出"：H3 假报回归。
